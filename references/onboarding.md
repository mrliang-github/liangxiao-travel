# 首次启用与恢复

只在首次启用、回复「继续」、配置报错或切换模式时读取本文件。

## 任务状态

每份旅行用独立的任务输出目录，例如 `outputs/my-trip/`。`brief.json` 接收：

```json
{"origin":"武汉","destinations":["成都"],"dateStart":"2027-05-01","dateEnd":"2027-05-04","people":2,"budget":"3000 元","preferences":"美食、拍照"}
```

这是结构示例，不是用户真实需求。仅使用用户已经提供的字段；不要补造必填项。`onboarding-state.json` 由脚本维护。恢复先读取其 brief，再检测，不依赖旧对话或旧 stage。文件损坏时保留原文件，不覆盖为假成功。禁止存凭据、手机号、验证码、身份或订单信息。

## stage 对应动作

| stage | 当前动作 | 完成后 |
|---|---|---|
| map_skill | 提供 WorkBuddy 技能市场的「腾讯地图助手」安装指引；来源为 TencentLBS/tencentmap-map-assistant。让用户确认安装 | 用户回复继续后重查，不能先说 Key 申请成功 |
| map_key | 读取已安装官方助手的 SKILL.md 与 tempkey-guide.md，接上手机号验证和自动保存流程 | 用户本人确认协议及手机验证；不回显完整 Key。官方助手保存成功后重查 |
| tongcheng | 引导 WorkBuddy → 插件/连应用 → 同程旅行（同程程心）→ 用户授权 | 回复继续后重查；不索要同程 Key，不在公共网页接收 token |
| plan | 检查 brief 中四项必填，缺项一次问清；开始对应 mode 的规划 | 实际查询失败仍需说明，不能以本地探测通过冒称服务可用 |

先展示当前一步，并说明做完回复「继续」。不要同时展开后面所有配置；不重复用户已提供的需求。官方助手未找到、网络失败或用户未同意时，说明当前问题并停在该步，保留需求。用户可主动选择「先做基础攻略」。

协议确认必须明确：先展示官方协议并让用户本人表示同意，再进入手机号验证；不能仅因收到手机号就推定已同意协议。宿主要求用户接管时遵守接管要求，不能代点同意或绕过权限确认。

## 模式切换

- 用户明确选择基础攻略：运行 `check_deps.py --state <任务>/onboarding-state.json --mode basic --json`。不读取个人 Key、不查询同程，产出有来源的公开资料、清单和基础安排；未知数值留空。
- 用户要求补充实际票价和地图：同命令换 `--mode guided`，重新检测；原有需求保留。
- 普通「继续」不加 `--mode`，沿用已保存选择。用户未选择时默认 guided，不自动降级。

## 安装前后的连接

首次访问公开网页尚未安装 Skill 时，网页负责下载 ZIP 与官方导入说明。安装后复制页面中的启动指令，在 WorkBuddy 新任务发送。网页无法确认安装或授权结果；不伪造完成状态，不臆造 `workbuddy://` 深链。

若用户只有旧版，先提醒升级到 1.2.0 或更新版本；未成功加载本 Skill 时不能声称本流程已经开始。正式发布前确保页面下载链接指向实际含本流程的安装包。
